# A — веб, сетевые сервисы и LLM

Документ задания задаёт: Nmap и Nessus/OpenVAS, ручной веб-тест, OWASP Web Top 10, LLM prompt injection / утечка system prompt / небезопасный вывод / обход ограничений, анализ конфигурации, CVSS 3.1, отчёт. Проверяйте только выданную цель и указанный диапазон.

Быстрый безопасный сбор доступности и заголовков:

```powershell
.\А_Веб_и_LLM\Скрипты\Собрать_паспорт_веб_цели.ps1 `
  -Uri 'https://target.example/' `
  -OutputDirectory 'E:\case\work\web'
```

Он делает ограниченные GET-запросы только к `/`, `/robots.txt`, `/sitemap.xml` и `/.well-known/security.txt`; тело ответа не сохраняет. Для опционального Nmap-сканирования популярных портов нужны оба параметра `-RunNmap -ConfirmAuthorizedScope`; это активный тест и допустим только для адреса из задания.

Скрипт создаёт `HTTP_проверки.csv` и `Паспорт_веб_цели.md`. Nmap не поставляется как portable-версия: если он установлен, можно добавить `-RunNmap -ConfirmAuthorizedScope`.

## Порядок на 3 часа

1. 0–15 мин: зафиксируйте границы проверки (scope), IP/URL, время, правила; проверьте доступность и сохраните исходные ответы.
2. 15–40: сервисы/порты; определите версии и поверхность атаки. Не запускайте агрессивные проверки, пока не подтверждён scope.
3. 40–110: веб вручную через браузер + Burp/ZAP: роли, авторизация, IDOR, ввод/вывод, загрузки, ошибки, API, сессии.
4. 110–145: LLM: прямые/косвенные инструкции, границы доступа, утечка данных, применение ответа к HTML/SQL/shell, инструменты/плагины.
5. 145–170: подтвердите находки безопасным минимальным PoC, оцените CVSS, исключите дубли.
6. 170–180: отчёт, доказательства, исправления, повторная проверка.

## Команды

```powershell
nmap -Pn -n -sV --top-ports 1000 -oA .\work\nmap <IP>
nmap -Pn -n -p- --min-rate 1000 -oA .\work\allports <IP> # только разрешённая сеть
nmap -Pn -sV -sC -p <порт-лист> -oN .\work\services.txt <IP>
```

Burp: браузерный proxy `127.0.0.1:8080` → Proxy/HTTP history → выделить запрос → Send to Repeater → менять один параметр за раз. ZAP: Manual Explore/Proxy; passive scan безопаснее активного. Сохраняйте raw request/response без секретов лишних пользователей.

## Чек-лист веб

- Аутентификация: слабое/повторное управление сессией, logout, reset, MFA.
- Авторизация: меняйте только свой ID/роль; проверяйте horizontal/vertical IDOR и серверную проверку прав.
- Инъекции: параметризированный SQL, шаблоны, shell, LDAP; ищите разницу в ответе/времени, не разрушайте данные.
- XSS/HTML: отражённый, хранимый, DOM; контекстное кодирование.
- SSRF/LFI/RFI/path traversal: только безопасные маркеры и разрешённые локальные тестовые файлы.
- Upload: расширение, MIME, содержимое, хранение вне webroot, выполнение, доступ.
- Конфигурация: debug, directory listing, секреты, TLS, CORS, security headers, default credentials.
- API: mass assignment, избыточные поля, rate limiting, GraphQL introspection только в scope.

## LLM-проверки

Готовый комплект тестовых промптов по OWASP LLM Top 10:2026 находится в `Инструменты/LLM_компоненты/Промпты_для_проверки_LLM_2026.md`. Используйте только тестовые canary-строки и мок-инструменты, не настоящие секреты/почту/shell. Вебовый OWASP Top 10 остаётся отдельной шпаргалкой `Инструменты/OWASP/Шпаргалка_OWASP_Top_10_2025.md`.

- Прямой prompt injection: просите нарушить правила в рамках тестового стенда; фиксируйте, какую конкретно защиту обошли.
- Косвенный: инструкция в предоставленном документе/странице попадает в контекст retrieval. Уточните, может ли модель выполнять её как команду.
- Утечка: просите тестовый секрет/системную инструкцию; не объявляйте утечку, если ответ лишь выдуман.
- Небезопасный вывод: проверьте, экранируется ли вывод перед HTML/SQL/командой/Markdown; докажите только безопасным безвредным маркером.
- Избыточные полномочия: какие tools доступны, есть ли подтверждение перед действием, границы пользователя/tenant.
- RAG: разграничение доступа к документам, stale data, prompt/data separation, цитирование источника.
- Обход отказа оценивайте только как часть конкретного риска/политики; сам по себе «модель ответила» не всегда уязвимость.

## CVSS 3.1 и запись находки

CVSS Base: AV (N/A/L/P), AC (L/H), PR (N/L/H), UI (N/R), S (U/C), C/I/A (N/L/H). Рассчитывайте официальным локальным калькулятором/таблицей, не придумывайте число. Отдельно укажите бизнес-влияние и условия.

Шаблон: ID/название; актив/endpoint; severity + CVSS vector; предпосылки; шаги воспроизведения; фактический результат; ожидаемый результат; доказательство (файл/строки); влияние; исправление; повторный тест.
