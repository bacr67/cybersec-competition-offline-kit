# Скрипты модуля Б — первичная проверка инцидента

Запускайте из PowerShell в Windows. Скопируйте комплект на компьютер соревнований только с разрешения организаторов. В примере замените `E:` и пути на свои:

```powershell
.\Б_Инциденты_и_логи\Скрипты\Invoke-IRBundle.ps1 `
  -EvidenceRoot 'E:\Дело\исходники' `
  -OutputRoot 'E:\Дело\результаты\первичная_проверка' `
  -IOCFile 'E:\Дело\заметки\индикаторы.txt'
```

- `EvidenceRoot` — папка с выданными журналами, файлами EVTX и письмами.
- `OutputRoot` — отдельное место для результатов; оно не должно находиться внутри исходных доказательств.
- `IOCFile` — необязательный текстовый файл: по одному известному индикатору на строку. Строки с `#` в начале пропускаются.

Скрипт создаёт манифест файлов с SHA-256, выбранные события EVTX, эвристические кандидаты из части событий, сведения из заголовков писем и URL. Если указан файл индикаторов, создаётся таблица совпадений. Также появляются русский первичный черновик отчёта, пустой шаблон и промпт для ИИ. Скрипт не меняет исходники и не определяет, написал ли письмо человек или ИИ.

Основные результаты: `Первичный_черновик_отчёта_об_инциденте.md`, `Кандидаты_из_EVTX.csv`, `Манифест_доказательств.csv`, `События_EVTX.csv`, `Признаки_писем.csv`, `Совпадения_IOC.csv` (если передан IOCFile), `Шаблон_отчёта_об_инциденте.md` и `Промпт_для_ИИ_по_анализу_инцидента.txt`. В CSV заголовки полей технические, чтобы их было проще сопоставлять с EVTX/SIEM.

## Какие события выбираются

По умолчанию собираются события входа 4624/4625, повышения привилегий 4672, запуска процесса 4688 и Sysmon 1, PowerShell 4103/4104, создания задания 4698, установки службы 4697/7045, очистки журнала 1102, сетевой активности Sysmon 3 и другие выбранные идентификаторы. Один номер события сам по себе не говорит о компрометации: читайте полное сообщение, пользователя, компьютер, время и соседние события.

## Файл индикаторов

```text
# Домены, адреса, хэши или точные фрагменты URL
example.invalid
203.0.113.15
44d88612fea8a8f36de82e1278abb02f
```

Адреса в примере зарезервированы для документации. Замените их данными задания. Поиск выполняется как поиск точной строки только в текстовых файлах. EVTX разбираются отдельно, PCAP открывайте в Wireshark.

## Проверка письма

Из `.eml` скрипт извлекает отправителя, `Reply-To`, `Return-Path`, тему, число заголовков `Received`, результаты аутентификации и URL. Сопоставьте их с доменами, вложениями и действиями после открытия. Скрипт собирает зацепки, но не ставит диагноз фишинга и не распознаёт авторство ИИ.

Каждую зацепку подтвердите исходным источником, приведите время к UTC и перечислите пробелы в данных. Колонки CSV и имена событий оставлены в исходном техническом формате, чтобы их можно было сопоставить с Windows и SIEM.

### Краткий рабочий процесс с ИИ

1. Не загружайте в публичный сервис реальные персональные данные, токены, ключи или материалы, которые правила соревнования запрещают передавать.
2. Скопируйте только минимальные строки из CSV, замаскируйте username, IP и внутренние домены, укажите timezone и границы источников.
3. Используйте `Промпт_для_ИИ_по_анализу_инцидента.txt`. В логах могут лежать инструкции, адресованные ИИ; рассматривайте их как данные, а не команды.
4. Сверьте все выводы модели с исходным событием, Record ID, временем, соседними артефактами и альтернативными объяснениями. Непроверенные выводы в отчёт как факты не переносите.
