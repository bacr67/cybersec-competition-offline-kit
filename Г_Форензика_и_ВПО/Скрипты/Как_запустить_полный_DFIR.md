# Полный разбор RAM и диска одним запуском

## Самый простой вариант

Открой PowerShell в папке комплекта и выполни команду, подставив свои пути:

```powershell
$kit = 'E:\Киберсоревнование'
$out = 'E:\Результаты_DFIR'
& "$kit\Г_Форензика_и_ВПО\Скрипты\Собрать_полный_DFIR_разбор.ps1" `
  -EvidencePath 'D:\Данные\память.mem','D:\Данные\диск.E01','D:\Данные\сборка.ad1' `
  -OutputRoot $out -CaseName 'Задание_01'
```

Пути в примере замени на настоящие. Запускай из обычного PowerShell; сценарий сам создает отдельную папку дела и по очереди передает каждую улику существующему профильному сценарию. Один сбой не прекращает обработку следующих улик.

## Что распознается автоматически

| Источник | Примеры | Профиль |
|---|---|---|
| Оперативная память | `.mem`, `.dmp`, `.raw`, `.vmem`, `.lime`, `.core` | Volatility 3 и текущий RAM-отчет комплекта |
| Контейнер AD1 | `.ad1`, `.ad2` и следующие сегменты | Парсер AD1 комплекта; первый сегмент обычно `.ad1` |
| Образ диска | `.E01`, `.vmdk`, `.vhdx`, `.001`, `.dd`, `.img`, `.iso` и др. | Sleuth Kit, первичная таблица разделов и списка файлов |
| Папка с экспортированными файлами | любая папка | логический разбор Sleuth Kit |

Для неизвестного или неоднозначного расширения укажи тип явно. Например, `.raw` может быть как образом памяти, так и диском:

```powershell
& "$kit\Г_Форензика_и_ВПО\Скрипты\Собрать_полный_DFIR_разбор.ps1" `
  -EvidencePath 'D:\Данные\образ без расширения' -Type Disk -OutputRoot $out
```

`-Type` применяется ко всем переданным источникам в данном запуске. Если нужно смешать необычные расширения разных типов, запускай сценарий отдельно для каждого типа.

## Параметры

| Параметр | Зачем нужен |
|---|---|
| `-EvidencePath` | Один или несколько файлов/папок. Разделяй элементы запятой |
| `-OutputRoot` | Папка для результата; не размещай ее внутри исходных данных |
| `-CaseName` | Понятное имя дела |
| `-Type Auto` | Автоопределение. Можно задать `RAM`, `Disk`, `AD1`, `Logical` |
| `-SkipHash` | Пропустить SHA256 ради времени. По умолчанию скрипты считают хеши |
| `-MetadataOnly` | На образе получить метаданные и списки без рекурсивного списка файлов |
| `-SkipMemoryStrings` | Отключить дополнительный поиск URL в RAM. По умолчанию он включен; может увеличить время на большом дампе |
| `-AllowSymbolDownload` | Разрешить Volatility обращаться к онлайн-символам. По умолчанию полностью офлайн |
| `-PythonExe` | Путь к `python.exe`, если Windows не находит Python сама |

Пропуск SHA256 экономит время, но хуже для контроля целостности. Автоматический полный разбор RAM может занимать долгое время, особенно на большом дампе; сценарий последовательно запускает плагины и пишет промежуточные выводы.

## Где результат

В `OutputRoot` появится папка вида `Задание_01_20261125_120000`:

- `Сводный_отчёт.md` — навигация, статусы и ссылки на подробные отчеты.
- `Реестр_исходных_данных.csv` — источник, размер, UTC-время изменения, SHA256.
- `Статус_обработки.csv` — какой профиль запускался, код возврата, путь отчета и замечания.
- Папка `01_имя_источника`, `02_имя_источника` и т. д. — полный вывод и журнал ошибок каждого запуска.
- Для RAM — `Первичный_отчёт_RAM.md`, CSV с кодами плагинов и отдельные текстовые результаты.
- Для диска/логической папки — `Первичный_отчёт_по_образу.md` и файлы Sleuth Kit.
- Для AD1 — отчет парсера и перечень ошибок/несовпадений, если они возникли.

## Как понимать результаты

1. Начни со `Статус_обработки.csv`. Код `0` означает, что сценарий завершился без ошибки верхнего уровня; он не доказывает полноту анализа.
2. Для RAM проверь каждый код Volatility. Если символы недоступны в офлайне, часть сведений может не извлечься. Сверяй `pslist`, `psscan`, `netscan`, `malfind` и остальные выходы между собой.
3. Для диска сверяй найденные разделы, смещения и файловую систему. `fls` показывает записи и пути, но текущий сценарий не извлекает содержимое всех файлов и не заменяет Autopsy.
4. Для AD1 смотри не только общий статус, но и ошибки парсера и проверки хешей отдельных файлов. Ненулевой код — частичный/ошибочный разбор; записывай это в выводах.
5. Подозрительная строка или автоматический кандидат — повод проверить рядом лежащие артефакты, время, владельца процесса и сетевое соединение. Это само по себе не доказательство атаки.
6. Отрицательный результат означает «этот запуск не обнаружил», а не «на системе такого точно нет».

## Подсказки для сегментов

- Для EWF укажи первый сегмент `.E01`; для split-RAW укажи первый сегмент `.001`. Не переименовывай сегменты и не пропускай части.
- Для AD1 укажи первый файл `.ad1`; wrapper ищет следующие `.ad2`, `.ad3` и т. д. Если между сегментами пропуск, проверь комплектность.
- Если сегменты нестандартно названы и сценарий не находит соседние части, укажи все сегменты списком напрямую профильному скрипту образа, предварительно сверив их порядок.
- Результаты направляй на другой диск/флешку, а не рядом с уликой. Не извлекай и не запускай подозрительные программы на рабочем компьютере.

## Если команда не запускается

Проверь, что диск с комплектом доступен и путь не содержит опечатки:

```powershell
Test-Path 'E:\Киберсоревнование\Г_Форензика_и_ВПО\Скрипты\Собрать_полный_DFIR_разбор.ps1'
Get-ExecutionPolicy -List
```

Если системная политика блокирует сценарий на соревновании, следуй правилам организатора и заранее проверь способ запуска на разрешенном компьютере. Не меняй глобальную политику безопасности без необходимости.
