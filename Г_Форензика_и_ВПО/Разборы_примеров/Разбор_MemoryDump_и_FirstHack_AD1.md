## Как запустить RAM-разбор

Открой PowerShell и выполни одной командой:

```powershell
$Kit = 'C:\Users\a-borisov\Downloads\Cybersec_Competition_Offline_Kit'
$Memory = 'C:\Users\a-borisov\Downloads\MemoryDump.mem'
$Out = 'C:\Users\a-borisov\Documents\Cybersec_Analysis\RAM'
& "$Kit\Г_Форензика_и_ВПО\Скрипты\Собрать_первичный_отчёт_по_RAM.ps1" `
  -MemoryPath $Memory `
  -OutputRoot $Out `
  -ScanMemoryStrings
```

Что означает команда:

- `$Kit`, `$Memory`, `$Out` — переменные с путями. Если папка комплекта или дамп лежат в другом месте, поменяй только значение соответствующей переменной.
- `&` запускает PowerShell-файл по пути, даже если в пути есть пробелы или кириллица.
- `-MemoryPath` передаёт исходный дамп.
- `-OutputRoot` задаёт отдельную папку для результатов. Скрипт специально запрещает писать отчёт рядом с исходным дампом.
- `-ScanMemoryStrings` включает дополнительный потоковый поиск строк URL, оканчивающихся на `.php`, в ASCII и UTF-16LE. Он не запускает найденные URL и не обращается к ним в интернет.

Сценарий использует Volatility 3 из локального wheelhouse. По умолчанию каждому плагину передаётся `--offline`, поэтому сеть для разбора не нужна. Если на новом компьютере отсутствуют Windows symbols, плагины могут завершиться с ошибкой. При доступной сети можно один раз разрешить загрузку символов:

```powershell
& "$Kit\Г_Форензика_и_ВПО\Скрипты\Собрать_первичный_отчёт_по_RAM.ps1" `
  -MemoryPath $Memory `
  -OutputRoot $Out `
  -AllowSymbolDownload `
  -ScanMemoryStrings
```

В текущем комплекте symbols были загружены один раз; окончательный контрольный запуск прошёл с `--offline`, все 9 плагинов завершились с кодом 0. На другом компьютере этот кеш может отсутствовать.

### Какие команды выполняет RAM-сценарий

Вручную запускать каждую не нужно: наш сценарий запускает их сам и сохраняет каждый результат в отдельный `.txt`. Внутренний синтаксис Volatility выглядит так:

```text
vol.exe -f "<путь-к-дампу>" --offline <плагин>
```

`-f` указывает исследуемый файл; `--offline` запрещает сетевую загрузку символов; последний аргумент выбирает проверку.

| Плагин | Что делает и зачем смотреть |
|---|---|
| `windows.info` | Определяет версию Windows, архитектуру и время снимка. Здесь: Windows 10, build 19041, время снимка `2023-05-21 23:02:39 UTC`. |
| `windows.pslist` | Показывает активное дерево процессов. Здесь видно `oneetx.exe` PID 5896 и дочерний `rundll32.exe` PID 7732. |
| `windows.psscan` | Ищет структуры процессов другим способом; сравнение с `pslist` помогает найти завершённые или пропущенные процессы. Само различие ещё не доказывает сокрытие. |
| `windows.netscan` | Ищет сетевые конечные точки, PID-владельца, адреса и состояние. Отсюда IP злоумышленника-кандидата и VPN-процесс. `CLOSED` означает, что соединение не было активным на момент снимка; запись всё ещё показывает найденный сетевой объект. |
| `windows.cmdline` | Показывает командные строки. Для `oneetx.exe` аргументы пустые (`-`), поэтому этот плагин не дал полный путь к EXE. |
| `windows.malware.malfind` | Ищет подозрительные области виртуальной памяти. `PAGE_EXECUTE_READWRITE` значит «можно читать, менять и исполнять»; `MZ header` указывает на начало PE-файла. Это сильный индикатор, но проверяй вместе с процессом и сетью. |
| `windows.dlllist` | Перечисляет загруженные модули процесса. В первом прогоне он падал на кириллице в пути среды Python; сценарий теперь задаёт UTF-8, контрольный прогон успешен. |
| `windows.filescan` | Ищет файловые объекты в памяти. Он дал путь `\Users\Tammam\AppData\Local\Temp\c3912af058\oneetx.exe`. |
| `windows.handles` | Показывает объекты, доступные процессам, включая ссылки на другие процессы. Используй для проверки связей PID, но не считай одну запись handle доказательством внедрения. |

### Почему ответы именно такие

**1. Подозрительный процесс — `oneetx.exe`.** В `windows.pslist.txt` PID 5896 найден активным процессом. В `windows.malware.malfind.txt` для этого же PID есть область `PAGE_EXECUTE_READWRITE` и `MZ header`. В `windows.netscan.txt` этот PID владеет соединением к `77.91.124.20:80`. Несколько разных артефактов сходятся на одном PID.

**2. Дочерний процесс — `rundll32.exe`.** В строке `windows.pslist.txt` поля идут как `PID PPID ImageFileName ...`. У `rundll32.exe` PID 7732, PPID 5896. PPID совпадает с PID `oneetx.exe`, значит это дочерний процесс.

**3. Защита памяти — `PAGE_EXECUTE_READWRITE`.** В строке `malfind` для PID 5896 поле `Protection` содержит это точное значение. Оно означает страницу памяти, которую процесс может читать, изменять и исполнять. В той же записи показан `MZ header`, поэтому это приоритетный участок для анализа.

**4. VPN — `tun2socks.exe`.** `windows.pslist` показывает процессы `Outline.exe` и `tun2socks.exe`. В `windows.netscan` сетевой объект с удалённой точкой `38.121.43.65:443` привязан к PID 4628 `tun2socks.exe`, поэтому он является наиболее точным ответом на вопрос о процессе, который обслуживал VPN-туннель. `Outline.exe` — связанный процесс-клиент, но сетевой объект в дампе назначен PID `tun2socks.exe`.

**5. IP — `77.91.124.20`.** В `windows.netscan.txt` есть строка `TCPv4 10.0.85.2:55462 -> 77.91.124.20:80 ... PID 5896 oneetx.exe`. Это сопоставляет удалённый адрес с подозрительным процессом.

**6. URL — `http://77.91.124.20/store/games/index.php`.** Сценарий нашёл эту строку в RAM шесть раз между ASCII и UTF-16LE. Она содержит тот же IP, который `netscan` связывает с PID 5896. Это наилучший ответ, поддержанный доступными данными. Для строгого доказательства браузерного посещения потребовались бы история браузера/кэш или HTTP-логи; найденная строка может быть URL, который использовал сам вредоносный процесс.

**7. Путь — `C:\Users\Tammam\AppData\Local\Temp\c3912af058\oneetx.exe`.** `windows.filescan.txt` содержит несколько файловых объектов с суффиксом `\Users\Tammam\AppData\Local\Temp\c3912af058\oneetx.exe`. Командная строка его не показала, поэтому путь берём именно из файлового сканирования, а не угадываем по имени процесса.

## Как запустить разбор FirstHack.ad1

```powershell
$Kit = 'C:\Users\a-borisov\Downloads\Cybersec_Competition_Offline_Kit'
$Image = 'C:\Users\a-borisov\Downloads\FirstHack.ad1'
$Out = 'C:\Users\a-borisov\Documents\Cybersec_Analysis\AD1'
& "$Kit\Г_Форензика_и_ВПО\Скрипты\Собрать_отчёт_по_AD1.ps1" `
  -ImagePath $Image `
  -OutputDirectory "$Out\FirstHack_AD1"
```

Параметры:

- `-ImagePath` — первый сегмент `.ad1`. Сценарий автоматически подхватывает соседние `.ad2`, `.ad3` и так далее; можно передать массив путей вручную.
- `-OutputDirectory` — отдельная папка отчётов, не папка исходного образа.
- `-ListOnly` — не сохранять выгрузку, но читать содержимое файлов для встроенной сверки MD5/SHA1.
- При первом запуске создаётся изолированное Python-окружение и ставятся локальные зависимости из `Инструменты\AD1\wheelhouse`; интернет не требуется.


### Что делает дисковый сценарий

Внутри он использует `tsk_imageinfo` для распознавания контейнера, `mmls` для таблицы разделов, `fsstat` для сводки файловой системы и `fls` для списка путей. Общая форма команд Sleuth Kit:

```text
tsk_imageinfo.exe "<образ>"
mmls.exe "<образ>"
fsstat.exe -o <начальный-сектор> "<образ>"
fls.exe -r -p -o <начальный-сектор> "<образ>"
```

`-o` — смещение раздела в секторах; `fls -r` перечисляет рекурсивно, `-p` показывает полные пути. Наш сценарий подбирает offset из таблицы разделов и складывает исходный вывод в отдельные файлы. AD1 разбирается отдельным сценарием через Dissect; не передавай контейнер AD1 напрямую инструментам Sleuth Kit.

## Ограничения и следующий шаг

- RAM-скрипт не выносит автоматический вердикт о заражении. `oneetx.exe`, область RWX, внешний IP и PHP URL — согласованные улики, которые усиливают гипотезу о вредоносной активности.
- `netscan` хранит найденные объекты соединений; `CLOSED` — не активная сессия в момент снимка. Адрес может быть инфраструктурой, связанной с процессом, но нужна дополнительная проверка.
- URL извлечён из строки в памяти; для доказательства посещения браузером проверь браузерный процесс, кэш/историю и связанный временной интервал.
- Путь из `filescan` не содержит букву диска. `C:\` — обоснованное предположение по Windows root, а не поле, выданное самим `filescan`.
- Для AD1 изучи `Первичный_отчёт_AD1.md`, `Ошибки_AD1.txt` и статусы в `Состав_AD1.csv`. В тесте FirstHack содержимое доступно частично; 29 ошибок и 3 несовпадения требуют ручной перепроверки. Обнаружение этих ошибок не даёт вывода о заражении или порче всего образа.
