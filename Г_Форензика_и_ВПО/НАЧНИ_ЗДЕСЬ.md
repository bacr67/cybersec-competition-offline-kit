# Модуль Г — цифровая форензика и базовый анализ ВПО

Сценарий включает RAM, образ диска, PCAP и подозрительный файл. Порядок: **свойства → процессы → сеть → инъекции → файлы → временная линия**. Исходники не менять. Запуск образца — только в изолированной VM организатора.

## 1. Манифест и анализ файла

```powershell
.\Г_Форензика_и_ВПО\Скрипты\Get-SampleStaticTriage.ps1 -Path 'E:\case\evidence\sample.exe' -OutDir 'E:\case\work\sample_static'
```

Скрипт выводит SHA-256, размер, время изменения, первые байты, подпись и readable strings (если доступен Sysinternals `strings.exe`). Он образец не запускает. Строка или плохая подпись — зацепка, но не доказательство malware.

## 2. Оперативная память: Volatility 3

Пакеты Volatility 3 находятся в `Г_Форензика_и_ВПО\Инструменты\Volatility3-wheelhouse`. Из корня комплекта:

```powershell
cd .\Г_Форензика_и_ВПО
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\Инструменты\Volatility3-wheelhouse volatility3
.\.venv\Scripts\vol.exe -h
```

Основные команды:

```powershell
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.info
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.pslist
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.pstree
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.cmdline
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.netscan
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.malfind
.\.venv\Scripts\vol.exe -f 'E:\case\evidence\memory.raw' windows.dlllist --pid 1234
```

`-f` задаёт RAM-файл. `pslist` перечисляет процессы; `pstree` показывает родительские связи; `cmdline` — команды запуска; `netscan` — сетевые endpoints; `malfind` ищет подозрительные области памяти; `dlllist --pid` — DLL конкретного процесса.

Сопоставляйте необычного родителя, командную строку, путь, сетевое соединение и участки executable/private memory. Один результат плагина не доказывает компрометацию. Некоторые плагины Windows могут запросить PDB symbols для конкретной сборки ОС; при неизвестной версии RAM dump гарантировать полностью офлайн-разбор нельзя.

## 3. Диск: Autopsy, Sleuth Kit и инструменты Eric Zimmerman

Запуск Autopsy: `Инструменты\Autopsy\autopsy-4.23.1\bin\autopsy64.exe`. Также добавлены Sleuth Kit CLI и Eric Zimmerman Инструменты, включая Registry Explorer, RECmd, MFTECmd, PECmd, LECmd, JLECmd, RBCmd, EvtxECmd и Timeline Explorer. Подробная шпаргалка: `Инструменты\Образы_дисков\Шпаргалка_по_образам_дисков.md`.

1. Зафиксируйте имя, размер, UTC-время и SHA-256. Базу дела и результаты сохраняйте отдельно от оригинала.
2. В Autopsy выберите `New Case` → `Add Data Source` → `Disk Image or VM File`. Для E01/split RAW выбирайте первый сегмент и оставляйте остальные рядом.
3. Выберите правильный timezone и проверьте `Data Source Integrity`, если есть исходный hash или внутренний checksum.
4. При нехватке времени начните с типов файлов, Recent Activity, ключевых слов и встроенных файлов; полный поиск свободного места может быть долгим.
5. Проверьте Timeline, Downloads, браузер/почту, LNK/Recent, Prefetch, Services/Tasks, Registry и EVTX. Экспортируйте только в рабочую папку.
6. Для RAW через Sleuth Kit: `mmls` → возьмите `Start` раздела → используйте это значение в `-o` для `fsstat`/`fls`. Не подставляйте offset из чужого примера.
7. Экспортированные копии `$MFT`, Prefetch, LNK, Jump Lists, `$Recycle.Bin`, EVTX и Registry hives разбирайте соответствующими Zimmerman tools; сохраняйте исходный путь артефакта.

Инструменты лежат в `Инструменты\Образы_дисков`. Registry Explorer/Timeline Explorer требуют .NET Desktop Runtime 10; установщик включён. Если поставить runtime нельзя, используйте Autopsy и консольные Zimmerman tools. Оригинальный образ не менять. Индексация может быть долгой — сначала смотрите наиболее полезные артефакты.

## 4. Windows артефакты: Sysinternals

Распакованные утилиты: `Инструменты\Sysinternals`.

```powershell
.\Г_Форензика_и_ВПО\Инструменты\Sysinternals\strings.exe -n 6 'E:\case\evidence\sample.exe'
.\Г_Форензика_и_ВПО\Инструменты\Sysinternals\sigcheck.exe -nobanner -a -h 'E:\case\evidence\sample.exe'
.\Г_Форензика_и_ВПО\Инструменты\Sysinternals\autorunsc.exe -accepteula -a * -c -h
```

- `strings` извлекает читаемые строки.
- `sigcheck` показывает подпись и hash.
- `autorunsc` перечисляет точки автозапуска текущего ПК.
- Process Explorer показывает дерево процессов; TCPView связывает PID и соединения; Procmon показывает операции процесса в работающей системе.

Не очищайте и не отключайте найденную persistence до фиксации доказательств. `autorunsc` на текущей ОС не равен анализу артефактов другого дискового образа.

## 5. PCAP: Wireshark

Откройте PCAP → `Statistics → Conversations` → DNS/HTTP/TLS → `Follow TCP Stream`. Полезные display filters:

```text
dns
http.request
tls.handshake.extensions_server_name
ip.addr == 192.0.2.10
tcp.stream eq 5
```

Display filter скрывает/показывает пакеты, не изменяя исходный PCAP. TLS payload обычно зашифрован.

## 6. Реверс: Ghidra

Ghidra и JDK распакованы. Из корня комплекта:

```powershell
$env:JAVA_HOME=(Resolve-Path '.\Г_Форензика_и_ВПО\Инструменты\JDK21\jdk-21.0.13.1+2').Path
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
& '.\Г_Форензика_и_ВПО\Инструменты\Ghidra\ghidra_12.2_PUBLIC\ghidraRun.bat'
```

В Ghidra: Import → Auto Analyze → Entry Point → Strings/Imports/Xrefs → Decompiler. Декомпилятор удобен для псевдокода; при сомнении проверяйте Listing/ASM и адреса функций. Ghidra не запускает sample автоматически.


### Быстрый первичный отчёт по образу

Из корня комплекта выполни:

```powershell
.\Г_Форензика_и_ВПО\Скрипты\Собрать_первичный_отчёт_по_образу.ps1 `
  -ImagePath 'E:\case\evidence\disk.E01' `
  -OutputDirectory 'E:\case\work\disk_triage' `
  -CaseName 'Дело 01'
```

Скрипт соберёт SHA-256 частей, сведения об образе, разделы, файловые системы и список файлов, затем создаст HTML/Markdown отчёты и CSV кандидатов. `.E02…` и `.002…` подхватываются автоматически. В комплектной версии Sleuth Kit подтверждены `raw`, `ewf`, `vmdk`, `vhd`; если формат не распознан, используй Autopsy. Для ручного выбора можно задать `-ImageType raw|ewf|vmdk|vhd`, `-SectorSize 512|1024|2048|4096`, `-Offset 2048` (сектор, не байт), `-TimeZone 'EST5EDT'`; подробности и пример передачи `.aa/.ab` списком — в `Скрипты\Памятка_по_скриптам.md`. `-MetadataOnly` ускоряет обход, но перечисляет только верхний уровень. На больших дисках SHA-256 и полный список файлов занимают время; `-SkipHash` отключает хэширование.

Если выдали папку с логически собранными файлами, укажи её одну с `-ImageType logical`: скрипт перечислит пути, но такой источник не содержит удалённых секторов и свободного пространства.

Совпадения — подсказки, не доказательство. Проверь каждую строку в Autopsy и сопоставь с временной шкалой, журналами и реестром. Исходный образ не меняется; каталог результатов укажи отдельно от папки с исходником.
