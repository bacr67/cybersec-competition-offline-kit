# Подготовка комплекта к флешке, Google Drive и Git

## Три копии для разных задач

- **Флешка / Google Drive:** полный комплект с инструментами и архивами. Текущий набор около 7,5 ГБ; отдельные файлы превышают 1 ГБ. Для флешки выбери NTFS или exFAT, не FAT32. Оставь запас свободного места для отчётов и дампа.
- **Git:** шпаргалки, сценарии PowerShell, карты, шаблоны отчётов и эта документация. Корневой `.gitignore` исключает основные бинарные инструменты, большие архивы, рабочие доказательства и картинки контроля вёрстки. Git-версия поэтому не является полным офлайн-комплектом.
- **Резервная копия:** отдельно сохрани исходные архивы инструментов, манифест хэшей и это руководство. Не держи единственную копию на одной флешке.

Скрипты и документы остаются в Git; полный комплект инструментов передавай отдельно через личное хранилище/флешку. До публичного репозитория проверь лицензию каждого бинарного пакета и условия его дальнейшего распространения. Наличие файла в комплекте не автоматически означает разрешение публиковать его.

## Что не добавлять в Git

- Образы дисков, дампы памяти, EVTX, PCAP, письма, выгрузки реестра и материалы самого соревнования.
- Пароли, токены, API keys, сертификаты, private keys, cookie, личные адреса и внутренние хостнеймы.
- Большие инструменты и runtime-архивы. `.gitignore` исключает основные каталоги `Инструменты`; перед первым `git add` всё равно проверь результат.
- Локальные папки `evidence`, `work`, `triage`, `.venv`, `Среда_Volatility3` и `render*`.

## Проверка перед публикацией

Из корня комплекта запусти аудит; отчёт уходит в `%TEMP%`, чтобы не попасть в публикацию:

```powershell
.\Проверить_комплект_перед_публикацией.ps1
```

Он ищет несколько распространённых шаблонов секретов в текстовых документах и показывает список файлов крупнее 50 МБ. По умолчанию каталоги поставщиков `Инструменты` не сканируются: аудируй лицензии и происхождение этих файлов отдельно. Сканер не гарантирует отсутствие секретов; просмотри его список совпадений и вручную проверь содержимое пакета.

Перед первым коммитом:

```powershell
git status --short
git check-ignore -v 'Г_Форензика_и_ВПО/Инструменты/Autopsy/autopsy-4.23.1.zip'
git check-ignore -v 'case/evidence/disk.E01'
```

Ожидается, что крупный Autopsy payload и evidence будут игнорироваться. Если Git показывает их в списке staged, остановись и удали их из staging до коммита.

## Контроль полноты копии

Сначала пересоздай список хэшей из корня комплекта. Скрипт проходит по всем файлам, поэтому на многогигабайтном наборе это может занять несколько минут:

```powershell
& '.\Общие_справочники\Создать_манифест_SHA256.ps1'
```

Сверь `Общие_справочники\Контрольные_суммы_SHA256.txt` после копирования. Сам файл манифеста исключён из него, чтобы список не хэшировал сам себя. Манифест относится к полному набору и исключён из Git-версии, где бинарные инструменты отсутствуют. Отдельный файл можно проверить встроенным PowerShell:

```powershell
Get-FileHash 'E:\Cybersec_Competition_Offline_Kit\Общие_справочники\Контрольные_суммы_SHA256.txt' -Algorithm SHA256
```

Полный комплект удобнее хранить как обычную папку или разбить на несколько архивов меньше 4 ГБ, чтобы не упереться в ограничения файловой системы/загрузки. Не архивируй повторно уже сжатые `.zip`/`.exe`, если это не экономит место; после копирования всё равно сравни SHA-256.
